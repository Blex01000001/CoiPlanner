# CoiPlanner：Captain of Industry 產線規劃工具

用 Blazor Server 做的「規劃與模擬」控制台。不連線遊戲，物品、配方與機器資料來自 `Data/*.json`，產線由使用者在 ComfyUI 風格的節點編輯器中自行規劃。

## 技術
- .NET 8、Blazor Web App（Interactive Server）、MudBlazor 9
- 節點編輯器：[@comfyorg/litegraph](https://www.npmjs.com/package/@comfyorg/litegraph) 0.17.2（MIT，放在 `wwwroot/lib/litegraph/`）
- 計算邏輯在 `Domain/`（不依賴 UI），測試在 `tests/CoiPlanner.Domain.Tests`（xUnit）

## 執行
```bash
dotnet run --project CoiPlanner.csproj
```
```bash
dotnet test
```

## 專案結構
| 路徑 | 內容 |
|---|---|
| `Data/*.json` | 物品（含運輸型態）、配方、機器與運輸方式資料；啟動時全部載入並驗證（目前是 `Data/game.json`） |
| `Domain/Models` | Product、Recipe、Machine、Transport、Node、ResourceSource、Edge、ProductionPlan；`Simulation.cs` 為模擬參數與狀態 |
| `Domain/Services` | `GameDataLoader`（載入資料）、`PlanCalculator`（規劃檢查、額定速率、運輸上限）、`ProductionSimulator`（逐步模擬）、`ProductionPlanSerializer`（規劃存取） |
| `Components/Pages/Home.razor` | 資料瀏覽 |
| `Components/Pages/Planner.razor` | 產線規劃（節點編輯器） |
| `wwwroot/js/graphEditor.js` | litegraph 包裝；只負責畫面，計算一律在 C# |
| `tests/CoiPlanner.Domain.Tests/Fixtures` | 測試專用的虛構資料，不會被網站載入 |

## 已改善
- 領域模型與 JSON 資料載入，含跨檔案的 id 與引用檢查
- MudBlazor 介面與資料瀏覽頁（物品、配方含每分鐘速率、機器）
- 產線計算：節點速率、物料平衡、規劃錯誤檢查
- ComfyUI 風格節點編輯器：拖動節點、依物品連線、調整機器數量，速率與錯誤即時顯示
- 規劃自動存在瀏覽器，可匯出／匯入 JSON、清空
- 節點可用 Delete 鍵或右鍵 → Remove 刪除
- 資源節點：以使用者輸入的每分鐘產量模擬原料供應（例如 Iron Ore）
- 產線規劃頁的畫布佔滿視窗，結果面板浮在畫布上且可收合
- 多個來源可以合流到同一台機器：同一個輸入插槽可以接多條線
- 輸入第一批遊戲資料（使用者提供）：抽水機、煤礦場、蒸氣鍋爐(煤)、鐵礦場、煉鐵廠、鑄鐵廠；移除示範用的虛構資料
- 流動動畫不會再穿透節點顯示；graphEditor.js 更新後瀏覽器會自動載入新版，不再沿用快取
- 節點的輸入／輸出插槽數量固定為配方的數量（例如煉鐵廠固定 2 個輸入、1 個輸出），合流不再多開插槽
- 流動動畫改成沿連線方向移動的箭頭；連線中間的圓點取消（點連線中間仍可開啟連線選單刪除）
- 取消最上方的 App Bar，選單改由左上角的浮動按鈕開啟，畫布佔滿整個視窗
- 匯入：可以把 .json 檔直接拖到畫布上匯入，不經過檔案選擇視窗
- SignalR 訊息上限由 32 KB 放寬到 2 MB，規劃較大時連線不會中斷
- 程序因未處理的例外結束時，會寫入 `logs/crash.log`
- 運輸方式（使用者提供）：管線（流體，5 級）、散裝運輸帶（散裝）、熔融通道（熔融物）、運輸帶（單件），後三者各 4 級；每種物品依型態只能走一種運輸，資料瀏覽頁新增「運輸」分頁
- 連線預設一級；點連線中間可選擇等級或刪除連線；計算會檢查運輸方式與等級是否正確
- 連線中間顯示「流量/上限」（每分鐘），達到上限時以紅色粗體標示；同一來源或目標有多條線時依建立順序填滿
- 產線改成逐步模擬（連續流量，每步 0.1 秒）：每個節點獨立運作，輸入都有料後等 1 秒才開始生產，缺料就停擺、不足就減產、下游收不下就堵塞；物料從源頭一路往下傳，看得出啟動的先後順序
- 模擬參數（使用者暫訂）：暫存 3 分鐘用量、運送 0.5 秒、啟動延遲 1 秒；沒接線的輸入視為 0（停擺），沒接線的輸出送進倉庫
- 面板可播放／暫停、切換 1×／5×／20× 速度、重置，顯示模擬時間；開頁或匯入後自動開始，修改產線時模擬繼續（匯入、清空時重新開始）
- 節點上方顯示狀態（運轉中／減產／啟動中／停擺原因），停擺的機器以橘色標示；插槽顯示「實際/額定」速率；箭頭速度隨流量改變，沒有流量時不動並變淡
- 物料平衡表改為模擬的實際產出、消耗與差額（最近 5 秒平均）

## 尚待改善
- 在 Visual Studio 偵錯時用「匯入」按鈕會中斷偵錯：在 Linux 上無法重現，推測是 VS 在檔案選擇視窗關閉後誤判瀏覽器已關閉而停止偵錯（未證實）。暫時請改用拖放匯入，或在 VS「工具 → 選項 → 專案和方案 → Web 專案」取消「瀏覽器視窗關閉時停止偵錯工具」；若仍閃退請提供 `logs/crash.log`
- 模擬參數（暫存、運送、啟動延遲）是暫訂值，不是遊戲資料，畫面上也不能調整；運送時間不隨連線長度變化
- 「依序填滿」的順序是連線建立順序，畫面上看不到也不能調整；前面的連線會先把下游 3 分鐘的暫存填滿，後面的連線在這段期間分到的料較少
- 機器以連續流量生產，沒有模擬遊戲中一批一批（週期）的產出
- 模擬狀態不會存檔，重新整理頁面後從 0 開始
- 把已存在的連線拖到別的輸入時，等級會回到一級
- 遊戲資料只有 6 種機器，其他產線尚未輸入
- 節點右鍵選單的 Clone 未測試，複製出的數量可能不正確
- 節點標題過長時會被截斷
